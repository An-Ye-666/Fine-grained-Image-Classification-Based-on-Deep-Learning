# 需求清单

来源：《科研项目组本科生考核任务书与操作指南》

本文件把任务书中的要求转换为可验收条目。具体描述与任务书冲突时，以任务书为准。

## 必做需求

| ID  | 需求        | 验收标准                                                       |
| --- | --------- | ---------------------------------------------------------- |
| R1  | 数据加载与分层划分 | 37 类完整；按 70/15/15 分层划分；训练、验证、测试无重叠                         |
| R2  | 数据预处理     | 训练集使用增强；验证和测试集使用确定性处理                                      |
| R3  | Baseline  | 预训练 ResNet-18；输出 37 类；完成 10 到 15 轮训练；验证集 Top-1 目标达到 80% 以上 |
| R4  | 训练记录      | 记录 Train Loss、Val Loss、Val Accuracy；保存最佳模型和训练日志            |
| R5  | 消融实验      | 选择 1 到 2 组单变量实验；记录 Top-1、Macro-F1 和耗时                      |
| R6  | 评估与分析     | 测试集指标、37 类混淆矩阵、错误案例分析                                      |
| R7  | 可解释性      | 选择正确和错误样本各 1 张生成 Grad-CAM                                  |
| R8  | 工程交付      | 模块化代码、依赖清单、README、清晰 Git 记录、一键复现                           |
| R9  | 技术报告      | 2 到 3 页 PDF，文件名符合任务书要求                                     |
| R10 | 答辩准备      | 能解释 Tensor 维度、数据增强、过拟合和梯度清零                                |

## 暂不作为目标

- 不要求设计全新网络结构；
- 不要求提出新的损失函数；
- 不要求达到论文级 SOTA 精度；
- 不要求增加额外数据集；
- 不要求为了展示复杂度而加入未经验证的模块。

## 需求追踪

后续每个实现任务、实验和交付物都应关联至少一个需求 ID。需求状态在 `docs/STATUS.md` 中维护。
